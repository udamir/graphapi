## 1. Introduction

A GraphAPI 1.0 document describes a GraphQL schema as a JSON value designed to be compared and processed by tools. Every named type is stored once under `components` as a definition whose `type` names its kind (`scalar`, `object`, `interface`, `union`, `enum`, `input`), with its members directly on the definition. Every reference to a type is a flat _type usage_ written next to the properties of the place it is used: `$ref` for every named type, custom scalars included, `type` for a built-in scalar, and `type: list` with `items` for a list. Operations and object fields share one shape: their own metadata, their `args` and the type usage of their result side by side. Directive usages are arrays of `{ $ref, meta? }`, so repeatable directives need no special form, and a deprecated element carries both its resolved deprecation reason and the `@deprecated` usage.

The design goal is that a change in the GraphQL schema shows up as a change in one place of the document. Type usages are flat, so a field changing from `String` to a custom scalar replaces `type: String` with one `$ref`, and a result type changing to another type changes only the type reference of that field. One nullability rule applies at every position (`nonNull: true` where the SDL writes `!`, nothing otherwise), so a nullability change touches only `nonNull`. Every definition carries an explicit `type`, every named type is referenced by `$ref`, so renaming a type changes only its key, its `title` and the `$ref`s to it, and directive usages are arrays, so adding a usage adds one entry.

This page is the normative definition of the 1.0 document. The key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are used as described in the [conformance section](/spec/#conformance) of the overview.

## 2. Conventions

### 2.1 Terminology

- **Document**: a JSON value (an object) conforming to this specification. It MAY be serialized as JSON or YAML.
- **Named type**: a GraphQL scalar, object, interface, union, enum or input object type.
- **Built-in scalar**: one of `Int`, `Float`, `String`, `Boolean`, `ID`.
- **Root operation type**: the object type the schema uses for `query`, `mutation` or `subscription`.
- **Component**: the description of a named type (a _definition_) or a directive definition stored under `components`.
- **Usage site**: a place where a type is used: an operation or field result, an argument, an input field, a directive argument or a list item.
- **Type usage**: the reference to a type at a usage site, written as fields of the usage site's object (`$ref`, or `type` and `items`, plus `nonNull`), see [section 4](#_4-type-usages).
- **Map[K, V]**: a JSON object whose keys are of kind `K` and whose values are `V`. Unless stated otherwise, producers SHOULD write map entries and array items in GraphQL declaration order, and consumers MUST NOT attach meaning to key order except where this page says so.

### 2.2 Data types

Field types in the tables of this page are `string`, `boolean`, `any` (any JSON value), `[T]` (array of `T`), `Map[string, T]` and the names of the objects defined below. A field marked **Required** MUST be present. An optional field MUST be omitted when it would hold its default (see [section 8](#_8-omitted-fields)); producers MUST NOT write `null` for an absent optional field.

## 3. Document structure

### 3.1 GraphAPI Object

The root of the document.

| Field                  | Type                                                               | Required | Description                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `graphapi`             | `string`                                                           | Yes      | The specification version. MUST be the string `"1.0"` (in YAML it MUST be quoted, since an unquoted `1.0` is a number).                         |
| `description`          | `string`                                                           | No       | The description of the schema definition (`"…" schema { … }`).                                                                                  |
| `directives`           | `[`[Directive Usage Object](#_5-11-directive-usage-object)`]`      | No       | Directive usages on the schema definition (location `SCHEMA`), including those added with `extend schema @d`.                                   |
| `queryTypeName`        | `string`                                                           | No       | Name of the query root type. Present if and only if the schema has a query root type, whatever its name.                                        |
| `mutationTypeName`     | `string`                                                           | No       | Name of the mutation root type. Present if and only if the schema has a mutation root type.                                                     |
| `subscriptionTypeName` | `string`                                                           | No       | Name of the subscription root type. Present if and only if the schema has a subscription root type.                                             |
| `rootTypes`            | [Root Types Object](#_5-13-root-types-object-and-root-type-object) | No       | Description, directive usages and implemented interfaces of the root operation types. Present only when at least one root type has any of them. |
| `queries`              | `Map[string, `[Operation Object](#_5-1-operation-object)`]`        | No       | The fields of the query root type, keyed by field name. Present if and only if the schema has a query root type.                                |
| `mutations`            | `Map[string, `[Operation Object](#_5-1-operation-object)`]`        | No       | The fields of the mutation root type. Present if and only if the schema has a mutation root type.                                               |
| `subscriptions`        | `Map[string, `[Operation Object](#_5-1-operation-object)`]`        | No       | The fields of the subscription root type. Present if and only if the schema has a subscription root type.                                       |
| `components`           | [Components Object](#_3-2-components-object)                       | No       | Every named type except the root operation types and the built-in scalars, and the directive definitions. Omitted when it would be empty.       |

The reference implementation writes the fields in the order of the table. Root operation types are described only through the operations maps, the `*TypeName` fields and `rootTypes`; they MUST NOT appear in `components`.

### 3.2 Components Object

Holds the named types and directive definitions of the schema, grouped by kind. The key of every entry MUST be the GraphQL name of the type or directive and MUST equal the entry's `title`.

| Field          | Type                                                                               | Required | Description                                                                                                                                        |
| -------------- | ---------------------------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scalars`      | `Map[string, `[Scalar Object](#_5-5-scalar-object)`]`                              | No       | Custom scalar types. Built-in scalars MUST NOT appear.                                                                                             |
| `objects`      | `Map[string, `[Object Type Object](#_5-6-object-type-and-interface-objects)`]`     | No       | Object types other than the root operation types.                                                                                                  |
| `interfaces`   | `Map[string, `[Interface Object](#_5-6-object-type-and-interface-objects)`]`       | No       | Interface types.                                                                                                                                   |
| `unions`       | `Map[string, `[Union Object](#_5-7-union-object)`]`                                | No       | Union types.                                                                                                                                       |
| `enums`        | `Map[string, `[Enum Object](#_5-8-enum-object)`]`                                  | No       | Enum types.                                                                                                                                        |
| `inputObjects` | `Map[string, `[Input Object Object](#_5-9-input-object-object)`]`                  | No       | Input object types.                                                                                                                                |
| `directives`   | `Map[string, `[Directive Definition Object](#_5-10-directive-definition-object)`]` | No       | Directive definitions: every custom definition, and the built-in definitions that are used or overridden (see [7.11](#_7-11-built-in-directives)). |

A section MUST be omitted when it would be empty, and the Components Object itself MUST be omitted when all its sections are. Types whose name starts with `__` (introspection types) MUST NOT appear. The `type` of every definition MUST match its section (`scalars` → `"scalar"`, `objects` → `"object"`, `interfaces` → `"interface"`, `unions` → `"union"`, `enums` → `"enum"`, `inputObjects` → `"input"`).

### 3.3 Reference Object

A reference is a `$ref` string holding a JSON Pointer fragment into the same document:

| Referenced element   | `$ref`                             |
| -------------------- | ---------------------------------- |
| Custom scalar        | `#/components/scalars/<Name>`      |
| Object type          | `#/components/objects/<Name>`      |
| Interface            | `#/components/interfaces/<Name>`   |
| Union                | `#/components/unions/<Name>`       |
| Enum                 | `#/components/enums/<Name>`        |
| Input object         | `#/components/inputObjects/<Name>` |
| Directive definition | `#/components/directives/<name>`   |

A **Reference Object** is a JSON object with the single field `$ref`; it is used where nothing but the reference is stored (`interfaces`, `implementedBy`, `oneOf`). In a [type usage](#_4-1-type-usage) and in a [Directive Usage Object](#_5-11-directive-usage-object), `$ref` is one field among the fields of the usage site (see [4.2](#_4-2-properties-of-the-usage-site)).

Every `$ref` MUST resolve to an entry of the document. Consumers MUST derive the referenced name from the last segment of the pointer.

## 4. Type usages

### 4.1 Type usage

A type usage is the reference to a type at a usage site. It is not an object of its own: its fields are written directly on the object of the usage site (an [Operation Object](#_5-1-operation-object) for a result, an [Argument Object](#_5-2-argument-object) for an argument, input field or directive argument), next to the site's own fields. Only the item of a list is an object that holds nothing but a type usage (`items`). A type usage takes exactly one of three forms:

| Form            | Fields                                                    | Used for                                                                                                    |
| --------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Named type      | `$ref: string` ([Reference](#_3-3-reference-object))      | Every named type stored in `components`: custom scalars, objects, interfaces, unions, enums, input objects. |
| Built-in scalar | `type: "Int" \| "Float" \| "String" \| "Boolean" \| "ID"` | The built-in scalars, which are not stored in `components`.                                                 |
| List            | `type: "list"`, `items: <type usage>`                     | A list type; `items` is an object holding the type usage of the list item, with its own `nonNull`.          |

Each form MAY be combined with `nonNull`:

| Field     | Type       | Required                 | Description                                                                                                                                                                                    |
| --------- | ---------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$ref`    | `string`   | One of `$ref` and `type` | A reference to a named type (`#/components/<section>/<Name>`, never `#/components/directives/…`).                                                                                              |
| `type`    | `string`   | One of `$ref` and `type` | The name of a built-in scalar, or `"list"`. A custom scalar MUST be referenced with `$ref`, never with `type`.                                                                                 |
| `items`   | type usage | With `type: "list"`      | The type of the list item. MUST be present when `type` is `"list"` and MUST be absent otherwise.                                                                                               |
| `nonNull` | `true`     | No                       | Present, with the value `true`, when the position is non-null (`T!`). Absent means nullable. Producers MUST NOT write `nonNull: false`; consumers MUST treat only `nonNull: true` as non-null. |

A usage site MUST carry exactly one of `$ref` and `type`. The key `type` is read by position: on a usage site it names a built-in scalar or `list`; on a [Definition Object](#_5-3-definition-object) it names the kind of the definition. A definition never carries `$ref`, `items` or `nonNull`.

### 4.2 Properties of the usage site

A usage site's own properties (`description`, `deprecation`, `directives`, `args`, `default`) sit next to the type reference, as siblings of `$ref` or `type`. They describe the usage site, never the referenced type: `description` on an argument is the description of the argument, and the description of the type it references is the `description` of that type's definition. In the example of [7.8](#_7-8-descriptions), `description: Find books` sits next to the result type of the operation `books` and describes the operation; the description of `Book` is on its definition. The same holds for a [Directive Usage Object](#_5-11-directive-usage-object), whose `meta` is a sibling of its `$ref`.

This is the trade-off of the flat form: an object with `$ref` is not a pure reference that may be substituted by its target. Tools that dereference `$ref` MUST NOT replace the usage object with the referenced definition and MUST NOT merge the definition into the usage object; they resolve the `$ref` string on its own and keep the fields of the usage. Generic JSON Reference resolvers that substitute every object containing `$ref` lose the description, deprecation, directives, arguments, default and nullability of the usage site, and are not suitable for 1.0 documents without that care.

### 4.3 Nullability

1.0 uses the same encoding at every position: operation results, object and interface fields, arguments, input fields, directive arguments and list items all carry `nonNull: true` when non-null (`T!`) and no `nonNull` key when nullable. No `required` lists exist and no `nullable` key exists.

The flag mirrors the `!` of the SDL one to one and defaults to `false`, as a GraphQL type is nullable unless it is marked with `!`. It needs no JSON Schema `required` array, and it avoids calling a position "required" where that would mislead: an operation result is never provided by the client, and a non-null argument or input field with a default does not have to be provided either.

Whether a client must provide an argument or input field is derivable: it MUST be provided if and only if it has `nonNull: true` and no `default`.

## 5. Objects

### 5.1 Operation Object

A field of a root operation type (in `queries`, `mutations`, `subscriptions`) or of an object or interface type (in `methods`). Both use the same shape: the field's own fields, its arguments and the [type usage](#_4-1-type-usage) of its result, side by side.

| Field                    | Type                                                          | Required | Description                                                                                                                            |
| ------------------------ | ------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `description`            | `string`                                                      | No       | The field description.                                                                                                                 |
| `deprecation`            | [Deprecation Object](#_5-12-deprecation-object)               | No       | Present when the field is deprecated.                                                                                                  |
| `directives`             | `[`[Directive Usage Object](#_5-11-directive-usage-object)`]` | No       | Directive usages on the field (location `FIELD_DEFINITION`); when the field is deprecated, the first entry is the `@deprecated` usage. |
| `args`                   | `Map[string, `[Argument Object](#_5-2-argument-object)`]`     | No       | The field arguments, keyed by name, in declaration order. Omitted when the field has none.                                             |
| `$ref` / `type`, `items` | [type usage](#_4-1-type-usage)                                | Yes      | The result type of the field: `$ref` for a named type, `type` for a built-in scalar, `type: list` with `items` for a list.             |
| `nonNull`                | `true`                                                        | No       | Present when the result is non-null.                                                                                                   |

Operation Objects MUST NOT carry `title`. The reference implementation writes the fields in the order of the table.

### 5.2 Argument Object

An argument of a field or directive definition, or an input object field: its own fields, the [type usage](#_4-1-type-usage) of its type and its default value, side by side.

| Field                    | Type                                                          | Required | Description                                                                                                                                                                   |
| ------------------------ | ------------------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `description`            | `string`                                                      | No       | The description of the argument or input field.                                                                                                                               |
| `deprecation`            | [Deprecation Object](#_5-12-deprecation-object)               | No       | Present when the argument or input field is deprecated.                                                                                                                       |
| `directives`             | `[`[Directive Usage Object](#_5-11-directive-usage-object)`]` | No       | Directive usages (location `ARGUMENT_DEFINITION` or `INPUT_FIELD_DEFINITION`); when deprecated, the first entry is the `@deprecated` usage.                                   |
| `$ref` / `type`, `items` | [type usage](#_4-1-type-usage)                                | Yes      | The type of the argument or input field.                                                                                                                                      |
| `nonNull`                | `true`                                                        | No       | Present when the type is non-null.                                                                                                                                            |
| `default`                | `any`                                                         | No       | The default value as a JSON value (see [section 6](#_6-values)). Present when, and only when, a default is declared; a declared `null` default is written as `default: null`. |

Argument Objects MUST NOT carry `title`. The reference implementation writes the fields in the order of the table.

### 5.3 Definition Object

Every named type component is a Definition Object: the common fields below, followed by the members of its kind, directly on the definition.

| Field         | Type                                                          | Required | Description                                                                                                                                                                  |
| ------------- | ------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `title`       | `string`                                                      | Yes      | The type name.                                                                                                                                                               |
| `type`        | `string`                                                      | Yes      | The kind of the definition: `"scalar"`, `"object"`, `"interface"`, `"union"`, `"enum"` or `"input"`. MUST match the components section (see [3.2](#_3-2-components-object)). |
| `description` | `string`                                                      | No       | The description.                                                                                                                                                             |
| `directives`  | `[`[Directive Usage Object](#_5-11-directive-usage-object)`]` | No       | Directive usages on the type (location `SCALAR`, `OBJECT`, `INTERFACE`, `UNION`, `ENUM` or `INPUT_OBJECT`), including those added with `extend … @d`.                        |

The members of each kind are listed in the following sections. A definition MUST NOT carry the members of another kind. The reference implementation writes `title` and `type` first, then `description`, `directives` and the members.

### 5.4 Element Object

The common shape of every element that can carry a description, a deprecation and directive usages. An [Enum Value Object](#_5-8-enum-object) is exactly an Element Object; Operation and Argument Objects extend it.

| Field         | Type                                                          | Required | Description                             |
| ------------- | ------------------------------------------------------------- | -------- | --------------------------------------- |
| `description` | `string`                                                      | No       | The description.                        |
| `deprecation` | [Deprecation Object](#_5-12-deprecation-object)               | No       | Present when the element is deprecated. |
| `directives`  | `[`[Directive Usage Object](#_5-11-directive-usage-object)`]` | No       | Directive usages on the element.        |

### 5.5 Scalar Object

A [Definition Object](#_5-3-definition-object) for a custom scalar:

| Field            | Type     | Required | Description                                         |
| ---------------- | -------- | -------- | --------------------------------------------------- |
| `type`           | `string` | Yes      | `"scalar"`.                                         |
| `specifiedByURL` | `string` | No       | The `url` of the scalar's `@specifiedBy` directive. |

### 5.6 Object Type and Interface Objects

[Definition Objects](#_5-3-definition-object) for object types and interfaces, with these members:

| Field           | Type                                                        | Required | Description                                                                                                                                                                             |
| --------------- | ----------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`          | `string`                                                    | Yes      | `"object"` in `components.objects`, `"interface"` in `components.interfaces`.                                                                                                           |
| `interfaces`    | `[`[Reference Object](#_3-3-reference-object)`]`            | No       | The interfaces this type implements, in declaration order. Omitted when it implements none.                                                                                             |
| `implementedBy` | `[`[Reference Object](#_3-3-reference-object)`]`            | No       | Interfaces only: every object and interface component whose `interfaces` contains this interface, sorted by type name. Root operation types are not listed. Omitted when there is none. |
| `methods`       | `Map[string, `[Operation Object](#_5-1-operation-object)`]` | Yes      | The fields, keyed by name, in declaration order (fields added by `extend` follow).                                                                                                      |

`implementedBy` is a derived reverse index: it MUST be consistent with the `interfaces` lists of the components, and its order (ascending by type name) does not depend on the order of definitions in the SDL. An Object Type Object MUST NOT carry `implementedBy`.

### 5.7 Union Object

A [Definition Object](#_5-3-definition-object) for a union, with these members:

| Field   | Type                                             | Required | Description                                                             |
| ------- | ------------------------------------------------ | -------- | ----------------------------------------------------------------------- |
| `type`  | `string`                                         | Yes      | `"union"`.                                                              |
| `oneOf` | `[`[Reference Object](#_3-3-reference-object)`]` | Yes      | The member types (`#/components/objects/<Name>`), in declaration order. |

### 5.8 Enum Object

A [Definition Object](#_5-3-definition-object) for an enum, with these members:

| Field    | Type                             | Required | Description                                                                        |
| -------- | -------------------------------- | -------- | ---------------------------------------------------------------------------------- |
| `type`   | `string`                         | Yes      | `"enum"`.                                                                          |
| `values` | `Map[string, Enum Value Object]` | Yes      | Every value of the enum, keyed by its (case-sensitive) name, in declaration order. |

An **Enum Value Object** is an [Element Object](#_5-4-element-object) (location `ENUM_VALUE` for its directives). A value without description, deprecation and directives is the empty object `{}`.

### 5.9 Input Object Object

A [Definition Object](#_5-3-definition-object) for an input object, with these members:

| Field        | Type                                                      | Required | Description                                            |
| ------------ | --------------------------------------------------------- | -------- | ------------------------------------------------------ |
| `type`       | `string`                                                  | Yes      | `"input"`.                                             |
| `properties` | `Map[string, `[Argument Object](#_5-2-argument-object)`]` | Yes      | The input fields, keyed by name, in declaration order. |

### 5.10 Directive Definition Object

| Field         | Type                                                      | Required | Description                                                                      |
| ------------- | --------------------------------------------------------- | -------- | -------------------------------------------------------------------------------- |
| `title`       | `string`                                                  | Yes      | The directive name, without `@`.                                                 |
| `description` | `string`                                                  | No       | The description.                                                                 |
| `locations`   | `[string]`                                                | Yes      | The directive locations (`FIELD_DEFINITION`, `OBJECT`, …), in declaration order. |
| `args`        | `Map[string, `[Argument Object](#_5-2-argument-object)`]` | No       | The directive arguments. Omitted when the directive has none.                    |
| `repeatable`  | `boolean`                                                 | Yes      | `true` for a `repeatable` directive, `false` otherwise. Always present.          |

A Directive Definition Object has no `type` field.

### 5.11 Directive Usage Object

One application of a directive to an element. Elements list their usages in a `directives` array in source order (usages on the definition first, then usages added by extensions); a repeatable directive applied several times produces one entry per usage.

| Field  | Type               | Required | Description                                                                                                                                                                                                                                        |
| ------ | ------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$ref` | `string`           | Yes      | The directive definition: `#/components/directives/<name>`.                                                                                                                                                                                        |
| `meta` | `Map[string, any]` | No       | The arguments given in the usage, keyed by argument name, as JSON values (see [section 6](#_6-values)). Only arguments written in the usage appear; default values of the definition MUST NOT be applied. Omitted when the usage has no arguments. |

### 5.12 Deprecation Object

| Field    | Type     | Required | Description                                                                                        |
| -------- | -------- | -------- | -------------------------------------------------------------------------------------------------- |
| `reason` | `string` | Yes      | The resolved deprecation reason: the given reason, or `"No longer supported"` when none was given. |

An element that is deprecated MUST carry both the Deprecation Object and, as the first entry of its `directives`, the usage `{ $ref: '#/components/directives/deprecated', meta: { reason } }` with the same reason; `components.directives.deprecated` MUST then be present. The default reason is always spelled out, both in `deprecation.reason` and in `meta.reason`.

### 5.13 Root Types Object and Root Type Object

The **Root Types Object** has the optional fields `query`, `mutation` and `subscription`, each a Root Type Object for the corresponding root operation type. An entry MUST be omitted when the root type has no description, no directive usages and implements no interface.

| Field         | Type                                                          | Required | Description                                                                                                                                                                                                                            |
| ------------- | ------------------------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `description` | `string`                                                      | No       | The description of the root type.                                                                                                                                                                                                      |
| `directives`  | `[`[Directive Usage Object](#_5-11-directive-usage-object)`]` | No       | Directive usages on the root type (location `OBJECT`).                                                                                                                                                                                 |
| `interfaces`  | `[`[Reference Object](#_3-3-reference-object)`]`              | No       | The interfaces the root type implements (`type Query implements Node`), in declaration order. This list is the only record of the implementation: root types are not components and are not listed in the interfaces' `implementedBy`. |

## 6. Values

Default values (`default`) and directive arguments (`meta`) are JSON values that keep their GraphQL type:

| GraphQL value                                   | JSON value                            |
| ----------------------------------------------- | ------------------------------------- |
| `Int`, `Float`                                  | number                                |
| `String`, `ID`, custom scalar given as a string | string                                |
| `Boolean`                                       | `true` / `false`                      |
| Enum value                                      | string holding the value name (`RED`) |
| List                                            | array of the item values              |
| Input object                                    | object keyed by input field name      |
| `null`                                          | `null`                                |

Falsy values (`0`, `""`, `false`, `[]`, `null`) are values like any other and MUST be written. The GraphQL type of a value is not stored next to it; consumers obtain it from the argument, input field or directive argument definition the value belongs to.

## 7. GraphQL to GraphAPI mapping

::: info Examples
Every YAML block on this page is the complete output of `gqlapi` (`buildFromSchema(buildSchema(sdl))`, graphql-js 17.1, dumped with js-yaml), unless labelled _(excerpt)_.
:::

### 7.1 Named types

| GraphQL definition                        | Stored as                                                           | `type` of the definition | Members on the definition                      |
| ----------------------------------------- | ------------------------------------------------------------------- | ------------------------ | ---------------------------------------------- |
| `scalar S` (custom)                       | `components.scalars.S`                                              | `scalar`                 | `specifiedByURL`                               |
| `type T` (not a root type)                | `components.objects.T`                                              | `object`                 | `interfaces`, `methods`                        |
| `type Query` (a root type)                | `queries` / `mutations` / `subscriptions`, `*TypeName`, `rootTypes` | n/a                      | n/a                                            |
| `interface I`                             | `components.interfaces.I`                                           | `interface`              | `interfaces`, `implementedBy`, `methods`       |
| `union U = A \| B`                        | `components.unions.U`                                               | `union`                  | `oneOf`                                        |
| `enum E`                                  | `components.enums.E`                                                | `enum`                   | `values`                                       |
| `input In`                                | `components.inputObjects.In`                                        | `input`                  | `properties`                                   |
| `directive @d`                            | `components.directives.d`                                           | n/a                      | `locations`, `args`, `repeatable`              |
| `Int`, `Float`, `String`, `Boolean`, `ID` | not stored                                                          | n/a                      | referenced as `type: <name>` at the usage site |

Fields, members and values added with `extend type`, `extend interface`, `extend input`, `extend enum` and `extend union` are part of the extended type, after the original ones. Types built without an SDL (code-first `GraphQLObjectType` and so on) are classified by their GraphQL kind.

### 7.2 Scalars

| GraphQL type at a usage site | Type usage fields                |
| ---------------------------- | -------------------------------- |
| `Int`                        | `type: Int`                      |
| `Float`                      | `type: Float`                    |
| `String`                     | `type: String`                   |
| `Boolean`                    | `type: Boolean`                  |
| `ID`                         | `type: ID`                       |
| Custom scalar `S`            | `$ref: '#/components/scalars/S'` |

Built-in and custom scalars are referenced differently on purpose: a custom scalar is a component and is always referenced with `$ref`, so replacing `String` by a custom scalar replaces `type: String` by a `$ref`. No `format` key exists in a 1.0 document.

::: code-group

### 7.4 Objects, fields and arguments

Object fields are the `methods` of the definition, with the same shape as operations. Arguments are a map of Argument Objects. The result type is written flat next to `args`: in `user`, `args`, `$ref` and `nonNull` are siblings.

```graphql [schema.graphql]
type User {
  id: ID!
  name: String
  tags: [String!]!
  friends(first: Int = 10): [User!]

type Query {
  me: User
  user(id: ID!): User!
}
```

### 7.5 Interfaces and unions

Implementing types list their interfaces in `interfaces`; interfaces list their implementations in `implementedBy`, sorted by name (here `Bot`, `Named`, `User`).

```graphql [schema.graphql]
  id: ID!
  name: String

type User implements Named & Node {
  id: ID!
  name: String
}

type Bot implements Node {
  id: ID!

  node(id: ID!): Node
```

### 7.9 Deprecation

`@deprecated` on a field, argument, input field or enum value produces a [Deprecation Object](#_5-12-deprecation-object) with the resolved reason and the `@deprecated` usage as the first entry of `directives`. The built-in `deprecated` definition is then included in `components.directives`.

| GraphQL                               | `deprecation`                     | `directives[0]`                                                                         |
| ------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------- |
| `@deprecated`                         | `{ reason: No longer supported }` | `{ $ref: '#/components/directives/deprecated', meta: { reason: No longer supported } }` |
| `@deprecated(reason: "Use distance")` | `{ reason: Use distance }`        | `{ $ref: '#/components/directives/deprecated', meta: { reason: Use distance } }`        |
| not deprecated                        | absent                            | no `@deprecated` usage                                                                  |

```graphql [schema.graphql]
enum Unit {

input Options {

}
```

### 7.10 Custom directives

Every custom directive definition is stored in `components.directives`. Usages are captured on every type-system location and stored in the `directives` array of the element they are applied to:

| Location                                                         | Where the usage is stored             |
| ---------------------------------------------------------------- | ------------------------------------- |
| `SCHEMA`                                                         | `directives` of the GraphAPI Object   |
| `OBJECT` (root type)                                             | `rootTypes.<kind>.directives`         |
| `SCALAR`, `OBJECT`, `INTERFACE`, `UNION`, `ENUM`, `INPUT_OBJECT` | `directives` of the Definition Object |
| `FIELD_DEFINITION`                                               | `directives` of the Operation Object  |
| `ARGUMENT_DEFINITION`, `INPUT_FIELD_DEFINITION`                  | `directives` of the Argument Object   |
| `ENUM_VALUE`                                                     | `directives` of the Enum Value Object |

Usages added through `extend schema @d` and `extend type T @d` (and the other type extensions) follow the usages of the definition. Each usage of a repeatable directive is its own entry, in source order.

::: code-group

```graphql [schema.graphql]
"Marks an element with a tag"
directive @tag(name: String!) repeatable on SCHEMA | OBJECT | FIELD_DEFINITION

directive @cost(weight: Int = 1, multipliers: [String!]) on FIELD_DEFINITION | ARGUMENT_DEFINITION

schema @tag(name: "public") {
  query: Query
}

type Product @tag(name: "catalog") @tag(name: "v2") {
  price(currency: String @cost(weight: 2)): Float @cost(weight: 5, multipliers: ["currency"])
}

type Query {
  product: Product
}
```

```yaml [graphapi.yaml]
graphapi: "1.0"
directives:
  - $ref: "#/components/directives/tag"
    meta:
      name: public
queryTypeName: Query
queries:
  product:
    $ref: "#/components/objects/Product"
components:
  objects:
    Product:
      title: Product
      type: object
      directives:
        - $ref: "#/components/directives/tag"
          meta:
            name: catalog
        - $ref: "#/components/directives/tag"
          meta:
            name: v2
      methods:
        price:
          directives:
            - $ref: "#/components/directives/cost"
              meta:
                weight: 5
                multipliers:
                  - currency
          args:
            currency:
              directives:
                - $ref: "#/components/directives/cost"
                  meta:
                    weight: 2
              type: String
          type: Float
  directives:
    tag:
      title: tag
      description: Marks an element with a tag
      locations:
        - SCHEMA
        - OBJECT
        - FIELD_DEFINITION
      args:
        name:
          type: String
          nonNull: true
      repeatable: true
    cost:
      title: cost
      locations:
        - FIELD_DEFINITION
        - ARGUMENT_DEFINITION
      args:
        weight:
          type: Int
          default: 1
        multipliers:
          type: list
          items:
            type: String
            nonNull: true
      repeatable: false
```

:::

`meta` holds only the arguments written in a usage: the usage on `currency` has no `multipliers`, and a bare `@cost` usage would have no `meta` at all although `weight` declares a default.

### 7.11 Built-in directives

The GraphQL specification defines `@skip`, `@include`, `@deprecated`, `@specifiedBy` and `@oneOf`. A directive definition with one of these names is **built-in** when its locations and argument names are those of the specification:

| Directive     | Locations                                                                                                            | Arguments |
| ------------- | -------------------------------------------------------------------------------------------------------------------- | --------- |
| `skip`        | `FIELD`, `FRAGMENT_SPREAD`, `INLINE_FRAGMENT`                                                                        | `if`      |
| `include`     | `FIELD`, `FRAGMENT_SPREAD`, `INLINE_FRAGMENT`                                                                        | `if`      |
| `deprecated`  | `FIELD_DEFINITION`, `ARGUMENT_DEFINITION`, `INPUT_FIELD_DEFINITION`, `ENUM_VALUE`, optionally `DIRECTIVE_DEFINITION` | `reason`  |
| `specifiedBy` | `SCALAR`                                                                                                             | `url`     |
| `oneOf`       | `INPUT_OBJECT`                                                                                                       | none      |

The locations MUST match as a set, apart from the optional ones; the argument names MUST match as a set. GraphQL implementations that also allow `@deprecated` on directive definitions (graphql-js 16.14 and later) therefore define the built-in `@deprecated`, not an override.

In a 1.0 document:

- A built-in definition MUST be stored in `components.directives` when, and only when, a directive usage in the document refers to it, so that the `$ref` of every directive usage resolves. This applies to `deprecated`, whose usage accompanies every deprecation, and to `oneOf`, whose usage marks a OneOf Input Object. `@specifiedBy` is encoded as `specifiedByURL` and is never a usage, and `@skip` / `@include` cannot be applied in a type system, so their definitions never appear unless overridden. A document without deprecations, `@oneOf` usages and custom directives has no `components.directives`.
- A definition with a built-in name but a different shape is an **override**. It is stored in `components.directives` like a custom directive, and its usages on scalars, objects, interfaces, unions, enums, input objects and the schema definition are stored as directive usages without a Deprecation Object. On fields, arguments, input fields and enum values a `@deprecated` usage always produces a Deprecation Object.

::: code-group

```graphql [schema.graphql]
directive @deprecated(reason: String = "No longer supported", since: String) on INPUT_OBJECT

input LegacyInput @deprecated(since: "2.0") {
  value: Int
}

type Query {
  run(input: LegacyInput): Boolean
}
```

```yaml [graphapi.yaml]
graphapi: "1.0"
queryTypeName: Query
queries:
  run:
    args:
      input:
        $ref: "#/components/inputObjects/LegacyInput"
    type: Boolean
components:
  inputObjects:
    LegacyInput:
      title: LegacyInput
      type: input
      directives:
        - $ref: "#/components/directives/deprecated"
          meta:
            since: "2.0"
      properties:
        value:
          type: Int
  directives:
    deprecated:
      title: deprecated
      locations:
        - INPUT_OBJECT
      args:
        reason:
          type: String
          default: No longer supported
        since:
          type: String
      repeatable: false
```

:::

A `@oneOf` usage is an ordinary entry of the input object's `directives`, and its definition is listed because the usage refers to it:

::: code-group

```graphql [schema.graphql]
"Exactly one way to identify a user"
input UserBy @oneOf {
  id: ID
  email: String
}

type Query {
  user(by: UserBy!): String
}
```

```yaml [graphapi.yaml]

queries:
  user:
    args:
      by:
        $ref: "#/components/inputObjects/UserBy"
        nonNull: true
    type: String
components:
  inputObjects:
    UserBy:
      title: UserBy
      type: input
      description: Exactly one way to identify a user
      directives:
        - $ref: "#/components/directives/oneOf"
      properties:
        id:
          type: ID
        email:
          type: String
  directives:
    oneOf:
      title: oneOf
      description: Indicates exactly one field must be supplied and this field must not be `null`.
      locations:
        - INPUT_OBJECT
      repeatable: false
```

:::

`printSchema` prints the usage (`input UserBy @oneOf {`) and, like every built-in, no `directive @oneOf` definition.

### 7.12 `@specifiedBy`

`scalar S @specifiedBy(url: "…")` is encoded as `specifiedByURL` on the Scalar Object (see the example in [7.2](#_7-2-scalars)). The usage MUST NOT appear in the scalar's `directives` and no `specifiedBy` definition is stored.

### 7.13 Schema definition and root operation types

The fields of the root operation types are the operations; the root types themselves are not components. Their names are always stored, their description, directive usages and implemented interfaces under `rootTypes`, and the schema definition's description and directives at the top level. A non-root type that is called `Query`, `Mutation` or `Subscription` is an ordinary component. Root types do not appear in `implementedBy` (in the example, `Node` has no `implementedBy`).

::: code-group

```graphql [schema.graphql]
interface Node {
  id: ID!
}

schema {
  query: RootQuery
  mutation: RootMutation
}

"Entry point"
type RootQuery implements Node {
  id: ID!
  query: Query
}

type RootMutation {
  ping: Boolean
}

"An ordinary type that happens to be called Query"
type Query {
  version: String
}
```

```yaml [graphapi.yaml]
graphapi: "1.0"
queryTypeName: RootQuery
mutationTypeName: RootMutation
rootTypes:
  query:
    description: Entry point
    interfaces:
      - $ref: "#/components/interfaces/Node"
queries:
  id:
    type: ID
    nonNull: true
  query:
    $ref: "#/components/objects/Query"
mutations:
  ping:
    type: Boolean
components:
  interfaces:
    Node:
      title: Node
      type: interface
      methods:
        id:
          type: ID
          nonNull: true
  objects:
    Query:
      title: Query
      type: object
      description: An ordinary type that happens to be called Query
      methods:
        version:
          type: String
```

:::

When printing a document back to SDL, `printSchema` emits a `schema { … }` block whenever the schema has a description or directives, a root type has a non-default name, or a non-root type is named like a default root type, so that the printed SDL re-parses to the same schema.

## 8. Omitted fields

Producers MUST omit an optional field when it would hold the value in the "Omitted when" column, and consumers MUST read an absent field as that value.

| Field                                                       | Object                            | Omitted when                                                                       |
| ----------------------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------- |
| `description`                                               | all                               | no description or an empty description                                             |
| `directives`                                                | all                               | no directive usages and, on deprecatable elements, not deprecated                  |
| `deprecation`                                               | Operation, Argument, Enum Value   | not deprecated                                                                     |
| `meta`                                                      | Directive Usage                   | the usage has no arguments                                                         |
| `nonNull`                                                   | Operation, Argument, list `items` | nullable (never `false`)                                                           |
| `args`                                                      | Operation, Directive Definition   | no arguments                                                                       |
| `default`                                                   | Argument                          | no default declared (a declared `null` is written)                                 |
| `interfaces`                                                | Object, Interface, Root Type      | implements no interface                                                            |
| `implementedBy`                                             | Interface                         | no component implements the interface                                              |
| `specifiedByURL`                                            | Scalar                            | no `@specifiedBy`                                                                  |
| `queryTypeName`, `mutationTypeName`, `subscriptionTypeName` | GraphAPI Object                   | the root type does not exist                                                       |
| `queries`, `mutations`, `subscriptions`                     | GraphAPI Object                   | the root type does not exist                                                       |
| `rootTypes` and its entries                                 | GraphAPI Object                   | no root type has a description, directive usages or interfaces                     |
| `components` and its sections                               | GraphAPI Object, Components       | empty                                                                              |
| built-in entries of `components.directives`                 | Components                        | no usage in the document refers to the built-in directive and it is not overridden |

The fields `graphapi`, `title` and `type` of definitions, `methods`, `properties`, `values`, `oneOf`, `locations`, `repeatable` and the `$ref` of directive usages are always present, and so is the type usage of every operation, argument and list item (`$ref` or `type`, and `items` with `type: list`). Enum values are always listed, as `{}` when they carry nothing.

## 9. Complete example

::: code-group

```graphql [schema.graphql]
"Todo API"
schema {
  query: Query
  mutation: Mutation
}

enum Color {
  RED
  GREEN @deprecated
}

type Todo {
  id: ID!
  name: String!
  color: Color
}

input TodoInput {
  name: String!
  color: Color = RED
}
```

## 10. Reading documents

A consumer of 1.0 documents (such as `printSchema` and `toIR`) reconstructs the GraphQL schema as follows:

- The kind of a named type is the `components` section it is stored in, which MUST agree with the `type` of its definition. The name of a referenced type or directive is the last segment of its `$ref`.
- A type usage is read from the fields of the usage site: `$ref` names a named type, otherwise `type` names a built-in scalar, or a list whose item is read from `items`. It is non-null if and only if `nonNull` is `true`; any other value or an absent `nonNull` means nullable. A usage site with both `$ref` and `type`, or whose `type` is neither a built-in scalar nor `list`, is an error, and so is a definition whose `type` does not match its components section. A usage site without `$ref` and without `type`, or with `type: list` and no `items` object, is an error. The other fields of the usage site are never read from the referenced definition (see [4.2](#_4-2-properties-of-the-usage-site)).
- When an element carries a Deprecation Object, its `@deprecated` usage is redundant and is not read as a separate usage; the Deprecation Object is authoritative. A `reason` of `""` is read as the default reason.
- A root type exists when its operations map is present; its name is the `*TypeName` field, or the default name when that field is absent.
- A document whose `graphapi` is not the string `"1.0"`, or that has no `graphapi`, is rejected.
- Documents that omit the specified directive definitions are read as if they contained them.

Reading a document and writing it again loses nothing: for a document built from a schema, `fromIR(toIR(doc))` deep-equals `buildFromSchema(schema)`.

## 11. Documents built from introspection

`buildFromIntrospection(introspection)` produces the same document as `buildFromSchema(schema)` for the same schema, with these differences, all caused by what introspection exposes:

- Custom directive usages are absent everywhere (schema, root types, types, fields, arguments, input fields, enum values). The `@deprecated` usages are present, since they are derived from the deprecation. `@oneOf` usages are absent, so the `oneOf` definition is not listed. Custom directive definitions are present.
- `description` of the document requires the introspection query option `schemaDescription`, deprecation of arguments and input fields requires `inputValueDeprecation`, `specifiedByURL` requires `specifiedByUrl`, and `repeatable` requires `directiveIsRepeatable` (it is `false` otherwise).

Default values are parsed from the introspection literals into the same JSON values as the SDL build.

```ts
import { buildSchema } from "graphql"
import { buildFromSchema, printSchema } from "gqlapi"
import type { GraphApiOperation, GraphApiSchema, GraphApiTypeUsage } from "gqlapi"

const doc: GraphApiSchema = buildFromSchema(buildSchema(sdl))
const todo: GraphApiOperation | undefined = doc.queries?.todo
const sdlAgain: string = printSchema(doc)

// the type usage is part of the operation itself; narrow it by its fields
const typeName = (usage: GraphApiTypeUsage): string =>
  usage.$ref !== undefined
    ? usage.$ref.slice(usage.$ref.lastIndexOf("/") + 1)
    : usage.type === "list"
      ? `[${typeName(usage.items)}]`
      : usage.type
const result: string | undefined = todo && typeName(todo) // "Todo"
```

`buildFromSchema`, `buildFromIntrospection` and `fromIR` return `GraphApiSchema`, and `printSchema` and `toIR` accept it.
